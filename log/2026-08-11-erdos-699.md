# 2026-08-11 — Erdős Problem 699 (common prime factors of binomial coefficients)

**Target.** Erdős Problem #699 (Erdős–Szekeres 1978): for every
1 ≤ i < j ≤ ⌊n/2⌋, is there a prime **p ≥ i** dividing
gcd(C(n,i), C(n,j))?  The strengthening (also open): outside a *finite*
exceptional set of triples (n,i,j) one can take **p > i**.  Statement pinned
from the Lean formalization (google-deepmind/formal-conjectures, fetched
today — primary); status "falsifiable" (= open, refutable by finite
computation) in teorth/erdosproblems `data/problems.yaml` (fetched today,
primary; `oeis: N/A`).  Known prior art, found by today's scoop scout and
cited prominently: an uncertified single-implementation Rust scan
(`conglu1997/erdos_699_rust`, 2026-01-03, posted on the erdosproblems.com
forum) verified the weak version for n ≤ 10⁷ (121 CPU-hours) plus thin
family sweeps n = 2^k ≤ 2²⁷ and n = 3^m+1 ≤ 3¹⁷+1, and recorded 9
strong-version failures.  The specific result attempted today, stated
before production: **an independent, dual-engine, certificate-carrying
verification of the weak version for all 4 ≤ n ≤ 10⁸ — ten times the
public bound — with the complete census of strong-version exceptional
triples on that range, each exception carrying an independently
re-verified certificate, plus proved reduction and structure lemmas.**
Pivot pre-committed to the three-move subtraction-game census (scout
candidate E2) if the production engines failed their control battery by
14:30 UTC.

**Result.**
- **CERTIFIED** — *Erdős Problem #699 (weak version, p ≥ i) holds for all
  4 ≤ n ≤ 10⁸*: no weak counterexample exists in that range.  Every pair
  (i,j), 1 ≤ i < j ≤ ⌊n/2⌋, has a prime p ≥ i dividing both C(n,i) and
  C(n,j).  This extends the public frontier (10⁷, single uncertified
  implementation, Jan 2026) by 10×, and upgrades it: dual independent
  engines (bitset and interval-list) cross-checked row-by-row on [4, 10⁶]
  and on spot slices at 5·10⁷ and 10⁸, full-pair Python reference
  equality on [4, 3000], independent Python row re-verification (shared
  no code) on sampled hard rows across the range, and three OEIS-anchored
  controls on the divisibility machinery (A129488, A263922, A030979 —
  205 terms reproduced exactly).  1.36·10⁹ hard rows examined; runtimes
  and per-chunk counters in `data/summary.csv`.
- **CERTIFIED** — *the complete census of exceptional triples for the
  Erdős–Szekeres strengthening (p > i) on 4 ≤ n ≤ 10⁸ is exactly the nine
  known triples*: (10,3,5), (16,2,6), (28,3,14), (28,5,14), (244,3,122),
  (512,2,147), (2048,2,713), (2188,3,1094), (1594324,3,797162) — **no
  tenth exceptional triple exists below 10⁸** (prior knowledge: the nine,
  from the Jan-2026 scan to 10⁷ + thin families to ≈1.3·10⁸; the complete
  dense census on (10⁷, 10⁸] is new).  Each triple ships a certificate
  (`certs/`) re-derived by an independent Legendre-valuation verifier and,
  for n ≤ 3000, by a third bigint-gcd path.  The (1594324,3,797162)
  triple, taken from the prior art and never fed to my code, was
  rediscovered by the sweep unprompted — the strongest cross-validation
  of the session.
- **PROVED** (elementary, NOTE §2) — the reduction scaffolding: (L1) for
  composite n with q = prevprime(n), every pair with i > n − q is
  witnessed by p = q, so only rows 2 ≤ i ≤ n − q ("hard rows") need
  checking; (L2) prime n is trivially clean via p = n; (L3) row i = 1 is
  clean via the classical n/gcd(n,j) | C(n,j); (L4) hard-row candidates
  are exactly the primes p > i dividing n(n−1)⋯(n−i+1), all ≤ n/2;
  (L5) every exceptional triple has i prime and p = i as its unique weak
  witness, with i | C(n,i) ⟺ n mod i² < i; (L6) if n−1 is prime, n has
  no hard rows — so n = 2^k with 2^k−1 a Mersenne prime can never carry
  an i = 2 exception, explaining the observed exponents {4, 9, 11}
  (2^k−1 composite) versus the Mersenne exponents {2,3,5,7,13,17,19}.
  L1–L5 are surely classical in substance (L1/L4 are implicit in how
  [ErSz78] found the examples; marked as such); the writeups are mine.
- **PROVED** (NOTE §4) — family mechanics: for n = 3^m+1, i = 3,
  j = n/2, the weak witness p = 3 always works (n ≡ 1 mod 9, and the
  base-3 carry at the top digit), and every candidate prime p > 3 divides
  3^{2m}−1, forcing the last base-p digit of j to be 0 or 1; the
  exception at a given m is decided by the higher digits, which the sweep
  certifies per m (m ∈ {2,3,5,7,13} exceptional; m = 4,6,8,…,16 not, up
  to 10⁸ covering m ≤ 16).  Analogous mechanism for i = 2, n = 2^k via
  the odd prime factors of 2^k−1.
- **Observation** (census-backed, not proved): every i = 3 exception has
  j = n/2 exactly; every exceptional n has the shape p^a + p^b of Kummer
  degeneracy (2^k = 2^{k−1}+2^{k−1}, 3^m+1, 28 = 3³+1); no exception has
  i ≥ 7.  The heuristic density argument for finiteness of each family is
  recorded as NUMERICAL in NOTE §5.

**What failed.**
- The interval engine's first draft could corrupt its interval list when a
  layer subtraction overflowed the buffer mid-prime (partial ping-pong
  state written back).  Caught in code review before any run; fixed by
  copy-in/copy-out semantics (overflow now leaves the list untouched and
  defers the prime to the per-element filter).  The lesson is standing:
  set-subtraction engines must be transactional per subtrahend.
- The A129488 OEIS control initially fired StopIteration: I had ignored
  the sequence's offset (it starts at n = 2 — C(2,1) = 2 has no odd prime
  factor at all).  Control-script bug, not engine bug; fixed by reading
  the %O line.  A reminder that OEIS offsets are part of the data.
- The first production launcher double-backgrounded worker 1 (an `&`
  inside an already-backgrounded shell), so its wrapper exited instantly
  and the timing file stayed empty; the sweep itself survived detached
  and was adopted via ps.  Cosmetic, but logged because a less lucky
  double-background would have silently killed the chunk.
- The NOTE's census table briefly carried gcd exponents written from
  memory while the run was in flight (2⁴ at n = 512 where the truth is
  2⁸; 3⁸ at 2188 where it is 3⁶).  `make_certs.py`'s bigint cross-check
  exposed all four wrong entries; the table now carries certificate
  values only.  "Every number in a note has a script that emits it" is
  not decorative.
- Not attempted by design: proving finiteness of the i = 2 family — it is
  equivalent to a Lucas-avoidance statement over the prime factorizations
  of Mersenne numbers 2^k−1, which is Mersenne-hard; the session took the
  certified-census route instead.

**Next.** (1) The dense range (10⁸, 10⁹]: the interval engine measures
~2.8 μs/row and the SPF sieve is the memory wall (4 GB at 10⁹ as u32) —
a segmented-sieve variant makes 10⁹ a one-session run.  (2) Prove the

j < n/2 always get covered — the two-digit structure of large candidate
primes should force this).  (3) The exceptional-triple sequence and the
exceptional-n sequence {10, 16, 28, 244, 512, 2048, 2188, 1594324} are
not in OEIS (`oeis: N/A` in the database; scout searched directly) — a
submission is the natural next artifact, but OEIS forbids AI-generated

the 10⁸ verification + census to the erdosproblems.com forum thread

scan is in `data/`.  (5) The margin question the prior art did not ask:
for each n, how large is the *second-smallest* valid prime across pairs —
i.e., how far above the exceptional configuration does the typical row
sit?  The sweep's uncovered-set machinery computes this at marginal cost.

### E1 — Erdős Problem #699 *(combinatorial number theory)* — SELECTED

*Statement.* As in Target, both versions, quantifiers pinned from the Lean
file (primary).  First nonvacuous n is 4; the i = 1 face is the proved
Erdős–Szekeres common-divisor theorem (= problem #698, proved by Bergman
2011, Lean-formalized Jan 2026), so the content is i ≥ 2.

*Source.* [ErSz78] = P. Erdős, G. Szekeres, "Some number theoretic
problems on binomial coefficients", Austral. Math. Soc. Gaz. 5 (1978)
97–99 (paper unreachable — everything attributed to it is (secondary) via
Bergman's abstract and erdosproblems.com snippets); the erdosproblems.com
page #699 (secondary snippets, statement wording matches Lean docstring
exactly); Guy UPINT B31 hosts the (28,5,14) example (secondary).

*Why believed open.* YAML status "falsifiable", last updated 2025-08-31,
formalized 2026-01-04, zero mentions in the AI-contributions wiki (frozen
Jun 30, 2026 — while neighbors #684, #698, #400 all have entries); the
2026 binomial-gcd arXiv cluster (Wu 2606.20940, Guo et al. 2606.22997)
proves *family* gcd theorems, not the pairwise same-row question; no
paper or preprint exists for the forum computation.  Scoop assessment:
MODERATE-HIGH for naive re-verification (the 10⁷ scan is public since
January), LOW for the differentiated deliverable (certified 10×
extension + census + lemmas), which is what was attempted.

*Feasibility (measured before selection).* My interval-list engine runs a
10⁵-wide slice at n = 10⁸ in ~28 s including sieve build (~2.8 μs/row
vs the prior art's 43.5 ms/row); [4, 10⁸] ≈ 1.5 core-hours total.
Measured, not estimated: the engines and all controls ran before the
production decision.

*Who cites it.* The erdosproblems.com page/forum for #699 (its
contribution culture mirrors Gordon's database), Bloom's problem
database, the Guy B31 circle, and the active 2026 binomial-gcd cluster.

### E2 — Three-move subtraction games: Flammenkamp's 1997 classification *(combinatorial game theory)* — pre-committed pivot

*Statement.* For S = {a,b,c}, the subtraction game's outcome sequence is
eventually periodic; Flammenkamp conjectures non-additive sets have
outcome period equal to a sum of two of the moves (with a fractal
selection rule), additive sets {a,b,a+b} purely periodic with
linear/quadratic periods.  Fresh theory: Larsson–Manabe arXiv:2603.10414,
Bhagat–Larsson–Manabe–Yamashita arXiv:2601.18715 (Jan–Mar 2026), which
also note the Winning Ways closed formula for {a,b,a+b} was never fully
proved (all (secondary)).

*Why not selected.* Excellent candidate — scout measured 1.41 ns/position
and found the competitive field empty (no data artifact on GitHub), with
a certificate design (window lemma) matching this repo's discipline.  Two
decisive negatives versus E1: Flammenkamp's own 1997 experimental range
is unknowable from here (his page egress-blocked — the same blocked-
frontier handicap that burned the 08-08 session), and the scout's own
prototype surfaced a convention landmine (all-odd move sets have minimal
period 2, so the conjecture's "period = sum of two moves" needs a
reading the blocked sources would have to settle).  Banked as the
strongest future CGT session, with the scout's `sub3.c` prototype and
measurements in this log's history.

### E3 — Canonical van der Waerden numbers H(3), H(4) *(arithmetic Ramsey)*

*Statement.* H(k) = least N such that every coloring of [N] with any
number of colors has a k-AP that is monochromatic or rainbow.  Fox–Hunter
(arXiv:2606.02541, Jun 2026) resolved the Erdős–Graham growth question
asymptotically; no exact H(k) value is recorded anywhere the scout could
find; trivially H(3) ≥ 9, H(4) ≥ 293 via w(k; k−1) (all (secondary)).

*Why not selected.* The 2023 Mao–Ozeki–Robertson–Wang JCTA tables (mono
or rainbow 3-APs of [9] under 3-colorings, etc.) sit in blocked PDFs and
may already contain the k = 3 answer — the exact silent-rediscovery trap
the 08-08 session fell into.  Third arithmetic-Ramsey-adjacent session in
five days would also cut against slate diversity.  Banked with the SAT
encoding sketch (partition variables + transitivity, DRUP-certifiable).

## 5. Tool discipline

Positive controls, all run before the production claims:
- **Full-pair reference**: pure-Python full-pair implementation (no
  reduction lemmas, both versions) cross-checked against a third
  independent path (bigint `math.comb` gcds factored by trial division)
  on [4, 150] — 0 mismatches — then census-equality with the C sweep on
  [4, 3000] (dual-engine): identical weak verdicts and identical
  exception lists.
- **Dual engines in production**: bitset and interval-list coverage
  engines cross-checked row-by-row (`--engine=both`) on all of [4, 10⁶]
  (9,097,742 hard rows, zero disagreements) and on spot slices at 5·10⁷
  and 10⁸.
- **OEIS anchors** (fetched from the oeis/oeisdata mirror, primary):
  A129488 (smallest odd prime dividing C(2n,n), 105 terms), A263922
  (highest exponent in C(2n,n) = max Kummer carries, 87 terms), A030979
  (C(2k,k) coprime to 3·5·7 — all 13 listed terms ≤ 25000 reproduced
  with no extras).  All PASS.
- **Prime-gap anchor**: per-chunk maxg values against the record-gap
  sequences A005250/A002386 (see `data/summary.csv` and README).
- **Sylvester–Schur tripwire**: the theorem guarantees every hard row a
  nonempty candidate set; the sweep asserts this on every row (zero
  SSVIOL across the run) — a control that would catch candidate-collection
  bugs in the dangerous (false-negative) direction.
- **Planted positive control**: the prior art's ninth triple
  (1594324, 3, 797162) was never given to my code; the sweep had to find
  it independently, and did, ~40 s into chunk B1.
- **Independent re-verification**: every exception re-derived by
  `verify_exceptions.py` (Legendre digit-sum valuations over all primes
  ≤ n — different formula, different code, no reduction), with selftest
  battery (8 real exceptions accepted, 3 fabricated near-triples rejected
  for the right reasons); sampled hard rows re-verified by
  `verify_row.py` (trial-division factoring + big-int tiling masks,
  no shared code).
- Determinism: no randomness anywhere in the production path (the row
  sampler uses a fixed LCG seed, recorded); runtimes, core counts and
  chunk boundaries in `data/summary.csv`; all engine sources sha256-able
  from the committed files.
